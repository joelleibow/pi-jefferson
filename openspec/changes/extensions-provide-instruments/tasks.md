Built from `design.md` (as amended for the spike gaps and Stage 5's two rounds), `design-review.md`,
the four delta specs and Derek's red/green proof in `redgreen-derek.md`. Each label names a spike rule
Derek ran red and green; the titles here are this plan's. Derek recorded
`A8 a bare name does not reach a provided instrument` as a **pin**, not a red — it was already true at

**Conventions.**

- Every command runs in this change's own checkout. `pnpm typecheck` and `pnpm test` are run there, and
  nowhere else.
- A worktree is allowed, and it gets **its own `pnpm install --frozen-lockfile`**. Its `node_modules`
  is a real directory: never symlink one in from another checkout.
- `pnpm` is never run in another checkout, and no task edits a file outside this checkout.
- **What a Verify means.** A Verify passes only when its output lists every test title the task names,
  each with ✔, and none with ✖. A run whose output lists only the file name ran nothing: a
  `--test-name-pattern` that matches no test still prints `✔ <file>` and exits 0. Every Verify names
  its file. A test that leaves an unhandled rejection prints ✔ for its title but ✖ for the file and
  exits 1, so that file line is its red.
- **One verify rule.** A task inside a group verifies with `pnpm typecheck` and
  `pnpm test --test-name-pattern "<its titles>" <file>`. Only each group's last task runs `pnpm test`,
  and that run must be green. The exceptions are 2.1, 2.3, 9.2 and 11.1, each of which runs whole
  files, which lists every title. 2.1 is a refactor with no test of its own, so its `pnpm test` must
  stay green unchanged.
- **A provided entry renders only once its name is registered before the read, until 6.3 lands.**
  Until then, every test that asserts a provided entry renders registers before the read: between
  `harness()` and `start()`, or between `session_shutdown` and the next `start()`. A test that
  registers after the read asserts rendering only from group 6 on.
- **Pin rows land with their files.** The export pin's coverage assertion fails as soon as a shipped
  `.ts` file exists without a row, so every task that creates a file or a runtime export adds that row
  in the same task, using the Interfaces key lists.
- **A test never passes first.** Where a task's test could pass the moment it is written, the task
  names its mutation or its guard; the coder runs it, sees red, reverts, and only then ticks.
- **Boundary cases.** Every task except a group-end or gate task carries a "Boundary cases:" line,
  `none` included.
- **Running a CI step locally.** Copy the working tree —
  `rsync -a --exclude node_modules --exclude .git ./ "$copy/"` into a `mktemp -d` directory — then run
  `pnpm install --frozen-lockfile` there, run the step's `run:` body from there, and remove the copy. A
  git clone carries only committed files, so it cannot show these checks red. Never install in this
  checkout.
