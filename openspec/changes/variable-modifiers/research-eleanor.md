## 1. Where the grammar and variables live; exact grammar, errors, undefined behavior

Defined/parsed/validated/resolved/documented/tested in exactly these places:

- **Parse + grammar:** `extensions/jefferson/format.ts:21` `parseFormat` (segments `FormatSegment` at lines 10-12: `literal` / `variable` / `bar`). Grammar as implemented today:
  - A backslash immediately followed by `$` yields a literal `$` and consumes both chars; any other backslash (including a trailing one) is a literal backslash (test: `rendered("model", "tail\\")` → `tail\`).
  - `$` starts a variable whose name is the maximal run matching `/^[A-Za-z0-9_]+/` after it. If that run is empty (end of string, or next char outside `[A-Za-z0-9_]` — so `$`, `$$`, `cost: $!` all qualify) it **throws** (format.ts:37): `"<instrument>"'s format has a bare $; escape a literal dollar as \$` (runtime message has a single backslash before `$`).
  - A name is declared iff `name === "bar" && declaration.bar !== undefined`, else `Object.hasOwn(declaration.variables, name)` — own properties only, so `toString`/`constructor`/`hasOwnProperty` are undeclared. Undeclared → **throws** (format.ts:41): `"<instrument>"'s format names a variable it does not declare: "$<name>"`.
  - A second `$bar` → **throws** (format.ts:45): `"<instrument>"'s format names a second width-taking variable: "$bar"`.
  - Literal text has control chars `\u0000-\u001F`, `\u007F-\u009F` collapsed to single spaces at parse time (`collapse`, format.ts:17, applied in `flush`). Empty format → `[]`. **`|` has no special meaning anywhere — it is an ordinary literal character today.**
- **Validation at config read:** `configuration.ts:91` `readInstruments` — rejects non-object `instruments` (`the instruments value is not an object`), non-object per-name entry (`the instruments configuration for "<name>" is not an object`), option keys not in `declaration.options` (line 109: `instrument "<name>" carries an option its declaration does not have: "<key>"`), non-string `format` (line 114: `instrument "<name>" has a format that is not a string`); wraps `parseFormat` errors and `validateStyle` errors (prefixed `instrument "<name>" `) as `RejectedConfiguration`. Cell-level: unrecognised cell key, missing/non-string `instrument`, bad `align`, empty `cells`, duplicate row `id`, both envelope shapes at once — all reject the document (messages in configuration.ts; pinned in `tests/configuration.test.ts`). Unknown instrument *names* (in cells or the section) do NOT reject: warning `… names instruments the extension does not implement: <names>; those cells render blank` (configuration.ts:270) and the cell renders `blank`.
- **Style validation:** `format.ts:64` `validateStyle`, `STYLE_KEYS` (line 60) = `fg, bg, bold, dim, italic, underline, inverse, strikethrough` (`satisfies Record<keyof ThemeStyle, true>`). Errors: `has a style that is not an object`; `has a style key that pi's ThemeStyle does not have: "<key>"` (own keys, so JSON `__proto__` keys are caught); fg/bg strings first tried against the live theme's `getFgAnsi`/`getBgAnsi` slot, non-token strings/numbers parsed once via pi-tui `parseColor` and kept as a `Color`, else `has an fg that is neither a foreground-slot theme token nor a color pi's parser accepts: <value>` (same for `bg`); attributes must be boolean else `has a style attribute that is not a boolean: "<key>"`.
- **Resolution:** `format.ts:107` `resolveFormat` — iterates **all** of `declaration.variables` via `Object.entries`; if **any** declared variable resolves to `undefined`, the **whole render returns `""`** (empty cell), even if the format doesn't reference that variable (test: "unknown suppresses the whole model declaration even under a model-only format"). Values are `collapse()`d, then substituted. `$bar` (only on declarations with `bar`): `barWidth = max(0, width − Σ visibleWidth(non-bar pieces))`; `filled = percent===null ? 0 : min(barWidth, floor(percent/100·barWidth))`; filled styled fg `error` if `percent > 90`, `warning` if `> 70` (`WARNING_PERCENT`/`ERROR_PERCENT`, format.ts:14-15, thresholds at 128-129), else the instrument style; track styled `{...style, dim: true}`; drawn as `█`/`░`.
- **Styling:** `styledPiece` (format.ts:102) — `""` → `""`; empty style → text unchanged; else `theme.style(text, style)`. Each literal and each variable value gets its **own** `theme.style()` call with the instrument's configured style, then segments are joined (format.ts:107-134).
- **Cell geometry:** `row-renderer.ts:20` `createFooter`; `cellView.render` memoizes by `(sample, width)`; `clipped = truncateToWidth(text, cellWidth)` (line 35); `pad = max(0, cellWidth − visibleWidth(clipped))` (line 36); pad split by `align` (left: after, right: before, center: `floor(pad/2)` before); trailing pad prefixed with `RESET` `"\x1b[0m"` (line 14) iff `leavesStyleOpen(clipped)` (line 16: contains `\x1b` and doesn't end with `\x1b[0m`) (line 40). Rows: `HStack` gap 0 (`GAP`, line 13), `addChild(component, {basis: floor(width/N), grow: 1, shrink: 0})` (line 63); `VStack` of rows built once; width change re-seats via `clear()`+`addChild`.

## 2. What the living specs require (exact titles + quoted sentences)

`openspec/specs/statusline/spec.md`:
- **"An instrument's format is plain text and variables"** — "A `format` MUST be plain text: literal characters render verbatim, and `$name` substitutes the value the instrument hands out for that variable, already formatted. The format language MUST NOT format a number, apply a style, or parse Markdown, and `[`, `]`, `(` and `)` are the characters they are. `$` is the only special character, escaped `\$`. A `$name` the instrument does not declare MUST reject the document, naming the instrument and the variable."
- **"An instrument's style is pi's ThemeStyle"** — "applied with `theme.style()`… plus the booleans `bold`, `dim`, `italic`, `underline`, `inverse` and `strikethrough`. The extension MUST NOT add style vocabulary of its own." Plus "A style MUST be resolved against the theme current at render time, and any styled text the extension caches MUST be rebuilt when the host invalidates the footer."
- **"An instrument's style is validated when its document is read"** — string fg/bg must name a token of the live theme's slot; other colors go through pi-tui's `parseColor()` at read time and are kept as a `Color`, "because `theme.style()` throws at render time on a raw color string and on a wrong-slot token. The host's token list MUST NOT be copied."
- **"$bar takes the width the rest of the format leaves"** — "MUST take the columns the rest of the format leaves in the cell, MUST shrink to nothing when nothing is left, and a format MUST hold at most one width-taking variable — a second MUST reject the document, naming it"; drawn from block characters in theme colors, "with no estimate to show it MUST draw its whole track unfilled in `dim`"; "no dependency the package does not already declare".
- **"Instrument text is bound by the row's geometry"** (clip at end + pad to full width) and **"A cell's alignment is the padding side inside it"** — "The pad MUST be measured in visible terminal columns, after clipping, never in code units"; ANSI scenario: "the pad carries none of that styling — which the renderer may achieve with a style reset before the pad — and the host's line-end style reset is untouched".
- **"A row is one line tall"** — "configuration validation MUST NOT police a format's text to keep it".
- Per-instrument requirements: **model** (`$provider`,`$model`), **thinking** (`$level`), **path** (`$path` = basename), **context** (`$tokens`,`$window`,`$percent`,`$bar`; null estimate hands out `?` and leaves `$bar` unfilled and dim; no usage → renders nothing), **tokens** (`$input`,`$output`,`$cacheRead`,`$cacheWrite`,`$totalTokens` = sum of the four, never `usage.totalTokens`), **cost** (`$cost`); each "MUST … render nothing" when its datum is unknown.
- **"An instrument is declared once, and every reader reads that declaration"** — "Adding an instrument MUST mean adding one declaration: no second table of names, and no edit to the configuration reader or the renderer that the new instrument's own shape does not require."
- **"An instrument's configuration lives in the extension's own document"** — top-level `instruments` object keyed by name, each value carrying only declared options; an undeclared option key rejects the document.

`openspec/specs/session-data-store/spec.md`: **"Unknown is a distinguished value"** (undefined, never `''` or `0`); **"A read is synchronous and total"** (never throws, even after dispose); freshness/derivation/invalidation/repaint/disposal requirements.

`openspec/specs/extension-source-layout/spec.md`: lines 4-5 (purpose: what ships in the tarball, which modules may depend on host packages), 30-44 (load root singular: `extensions/` convention or `package.json` `pi.extensions`, exactly one), 48-61 (no test file in the tarball; tests under `tests/`), 79-85 ("The published file set is deliberate": tarball = exactly `package.json` `files` + npm mandatory files; CI asserts by invariant — allowed roots, entry presence, no test files, load root value — not an enumerated list; root/entry/load-root changes must update `files`, manifest and CI expectation together), 139-150 ("Host packages are the host's to supply, and imports run one way": `peerDependencies` `*`, MUST NOT appear in `dependencies`, "so exactly one copy reaches the process"; any shipped file MAY import a host package at runtime).

## 5. How styling is applied and closed today

- Instrument `style` from `pi-jefferson.json` → `validateStyle` at read time (format.ts:64) → `ConfiguredInstrument.style` → closed into the bound `render` (configuration.ts:74-88) → `resolveFormat` → **per segment** `styledPiece(piece, style, theme)` → `theme.style(text, style)` (format.ts:102-105). Empty style ⇒ raw text; empty text ⇒ `""`.
- `$bar` pieces: filled with `{...style, fg: "error"|"warning"|style}` (format.ts:128-129), track with `{...style, dim: true}` (format.ts:130-131).
- Cell: `truncateToWidth` clip, `visibleWidth` pad, `RESET` before a trailing pad iff `leavesStyleOpen` (row-renderer.ts:14-16, 35-40). The host frames each child (`"\x1b[0m\x1b]8;;\x07"` per `tests/row-renderer.test.ts` FRAME helper) and resets between children, so only the intra-cell pad needs our reset.
- A per-variable modifier style would have to pass through `resolveFormat`'s per-segment `styledPiece` call (between substitution and join) and would then be exposed to the `leavesStyleOpen`/RESET pad rule. The render-time theme is the object handed to the `setFooter` factory (jefferson.ts:120); the footer closes over it (row-renderer.ts:20) and cell memos are dropped on `invalidate()`.
