# Codebase research: bar thresholds

Repository: `/Users/joelleibow/Projects/pi-jefferson` (branch `bar-thresholds`). Read-only investigation; this report is the only requested write. Owner rulings and plan context were read in full: `openspec/changes/bar-thresholds/owner-rulings.md` and `plan-context.md`. Binding points relevant to implementation: default thresholds are 70/90 but use `>=`; configured list replaces defaults; threshold options are independent of one another and fall back to top-level/default; `style` remains instrument-wide, `fill` styles bar fill; top-level `fill` exists; cap is four lowest threshold values (excess warning, not rejection); malformed/noninteger/out-of-range/duplicate activeAt rejects the document; unknown percentage means 0. Provider opts in via declared `options`; non-opt-in bar remains default. No solution design is proposed below.

## 1. Existing bar

- `extensions/jefferson/components/visuals/bar.ts:14-15` defines fixed 70 and 90. `:18-26` computes fill with clamp/floor, colors only the filled segment, and dims the remainder track. The current comparisons are strict: `percent > 90` error, else `percent > 70` warning (`:21-22`); the exact-boundary behavior is therefore not the owner-ratified `>=` behavior.
- Caller: `extensions/jefferson/format.ts:295-303` detects a bar segment, invokes declaration `bar`, returns blank for `undefined`, calculates available width from `width - nonBar` and calls `drawBar(barWidth, percent, style)`. Theme styling of the resulting parts follows at `:302-303`.
- Pinned boundaries/tests: `tests/format.test.ts:147-153` explicitly proves current strict edges: 70 retains accent, 70.1 warning, 90 warning, 90.1 error. `:163-170` pins clamping/flooring and over-100 behavior. Null track behavior is at `:157-160`; zero width at `:130-135`. `tests/jefferson.test.ts:524-538` pins end-to-end width and proportional fill; `:685-727` covers real-bar row allocation and no room. `tests/instrument.test.ts:180-189` distinguishes unknown context from known null estimate. `tests/configuration.test.ts:700-714` tests label/prose reducing bar width; `:1240-44` styles it end-to-end. `tests/registration.test.ts:1415-1444,1836-45` cover provided bar and negative percentage. These are bar tests; a repository-wide search found no other explicit 70/90 edge assertions besides `format.test.ts`.
- Docs/model explanation: `ARCHITECTURE.md` “Visuals” and “Instrument” sections describe `$bar` and available columns; `AGENTS.md` “Adding an instrument” and width-zero rule. `docs/adr/0009-the-components-hold-the-parts-and-the-bar-stands-alone.md` describes the standalone visual. Current color policy additionally connects format color precedence: `docs/adr/0021-a-foreground-colour-of-the-theme-is-a-modifier.md`.

## 2. Settings to render

- Configuration entry is `extensions/jefferson/configuration.ts`; per-instrument settings are validated against the instrument declaration and live theme, then stored/bound. The architecture summary says errors for Jefferson-owned settings reject the whole document and default row, whereas provided-instrument setting faults refuse only that instrument (`ARCHITECTURE.md`, Configuration section).
- Instrument declarations: `extensions/jefferson/components/instruments/instrument.ts:14-21` defines render and `:49` onwards foundational options; `FOUNDATIONAL_OPTIONS` is `format`, `style`, `label` at `:62`. Bound instrument carries parsed segments/style/label/formats in `components/instruments/instrument-binding.ts:13-22` (configured shape) and binds/render-selects them later in that file (`:287-307`); inspect exact current implementation before editing.
- Configuration parsing/validation is in `configuration.ts`: notable branches `:139-141` describe provided options; `:202-237` parse composed formats in the provided-settings path; `:309-347` parse regular instrument options and composed formats. Error fragments include formats not object, unknown composed kind, non-string format and parse failure (`:208-233` and `:319-331`). This distinction is material: ordinary document failures reject the document; provided settings use instrument-scoped refusal per architecture.
- Rendering and variable resolution: `format.ts:287-303` resolves named segments; an unknown named variable blanks its instrument and `undefined` bar blanks when `$bar` is named. `instrument-binding.ts:293-306` prepares label and composed formats; configured composed values are selected at render. ADR 0012 is `docs/adr/0012-a-composed-format-is-chosen-by-a-reading.md`; architecture says a reading chooses the composed format and binding passes resolved plain text through the declared variable.
- Width rule: `AGENTS.md` “Adding an instrument”, item 4, requires width-0 text to match width-200 for shipped instruments unless it fills. `components/row/row-renderer.ts` probes text at width 0; format rendering allocates `$bar` only from actual render width (`format.ts:300-302`). This makes `$bar` a fill/width-taking format, distinct from ordinary content sizing.

## 3. Bar declarations / data behavior

- Contract permits `bar?: (readings) => number | null | undefined` and documents null as unfilled, undefined unknown: `extensions/jefferson/instrument-contract.ts:41-42`.
- Shipped bar-capable instrument is context: declaration at `extensions/jefferson/components/instruments/context.ts` (search/read declaration for exact lines); `tests/instrument.test.ts:84-86` asserts only context has a bar function; `:95-98` pins the shipped list. Its bar derives from context usage percent; no usage/unknown resolves undefined; known missing estimate resolves null. `tests/instrument.test.ts:180-189` pins unknown blank versus null empty track.
- Negative percentages are accepted as finite bar values and rendered as zero filled cells, not provider fault: `bar.ts:19-20`; provider binding validates finite number or null and rejects invalid type/nonfinite (`instrument-binding.ts:179-186`); `tests/registration.test.ts:1836-45` pins negative unfilled track.
- Context fallback when pi has not reported anything is the fallback/default context instrument and unknown bar behavior; `extensions/jefferson/shipped.ts` contains the fallback definition. `$percent` output is unknown rather than a numeric estimate as pinned in `tests/format.test.ts:157-160`.

## 6. Warnings

Warnings exist today: missing instrument registration and runtime/provider faults are reported through the faults/registration path; configuration parsing produces warning data. `ARCHITECTURE.md` says configuration errors reject the whole document and warn with the cause, unknown registration warns once startup completes and draws blank, and provided settings refuse only that instrument and warn once. Relevant files are `extensions/jefferson/faults.ts`, `configuration.ts`, `startup.ts`, `registration-listener.ts`; tests include `tests/configuration.test.ts` and `tests/registration.test.ts`. Thus a loadable warning mechanism exists in principle; the new over-four condition is ruled to warn rather than reject. User-facing delivery details should be checked in those files before implementation.
