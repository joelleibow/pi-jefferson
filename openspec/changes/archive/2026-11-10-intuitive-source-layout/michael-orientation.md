## 4. The strongest challenge to doing the change as stated

The tree already satisfies the only layout rule on record, under that rule's own words, four days after Joel approved it. Of the three premises the complaint rests on, two are false in source (instruments are one file, not many; the bar is at `format.ts:196-206`) and the third is a quarrel with the adjective "visuals", not with where anything sits. A restructure that answers the adjective costs: 40 test specifiers and a pin rewritten and re-argued for every new file; a new ADR revising ADR 0005 and a note keeping ADR 0007 true; `--follow` history lost for every line a split moves; stale citations in a PL4-approved design on the paused branch, and a re-gate of it if any top-level name moves; and a published patch release nobody can observe. Joel's own 2026-11-06 standard — *"nominal structure to not be overbearing"* — cuts against ten 8-line instrument files as much as it cut against `config/` holding one file.

So the test the design must pass before any file moves: for each move, name the thing a browsing reader looked for, where they looked, and where it was — and show the new path answers it. The bar is the one such case on record. If the design cannot produce that sentence for `width-plan.ts`, `instrument-binding.ts` and `format.ts`, moving them is ceremony and the finding is that they stay, with their headers and `ARCHITECTURE.md:16` (which lumps six files into one line) saying what they are.

**What I would choose, and why (no decision settles it; proposed unrun):** keep the five top-level homes exactly as ADR 0005 placed them — the paused design and its research are written against those names. Do the work inside `visuals/`: give instruments a directory only if Joel confirms one-per-file (ADR 0005:24-25 then requires the directory, and the three new instruments slot in as three files), export each declaration and pin them; give `$bar` a findable home by name — at minimum the format file's header and a `bar` line in `ARCHITECTURE.md`'s parts map, since the drawing is six lines of `resolveFormat` and a separate file would need a new export and a new pin to say what one comment says; and rename or regroup the rest only under the nouns Joel has already ruled (instrument, cell, row), never under adjectives or `common/`/`helpers/` names (spec `:105-106`). Every new directory carries its membership and import rule in the design (spec `:106-108`), the import rule stays ADR 0005:37-38 extended to the new directories, and the proof is §2's seven checks attached to the change.
