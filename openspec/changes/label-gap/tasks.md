# Tasks

Conventions for every task below, stated once:

- **Sources.** `owner-rulings.md` (Joel's rulings, binding), the approved `design.md` (D1 to D8), `specs/statusline/spec.md` (the delta), and the reports `research-eleanor.md` (with its addenda), `research-chidi.md`, `michael-orientation.md` and `council.md`. Each task names the one it rests on. Line numbers are at HEAD `ad0e28f`, where Eleanor measured them, and they shift as the tests change.
- **Test first.** A task that adds behavior starts with a test whose name is a behavioral assertion and which fails against the unchanged code. A task that only *guards* a mistake (the test passes on the correct code) says so and names the mutation that shows the test catching it. Michael's PL7 gate runs (`58e3125c-6ea3-4141-aed4-d6fbc6c46d95` and `49dfd3c9-f29a-450a-840a-e88e046b4323`) measured the mutation mapping on his own scratch implementation, and the mapping reproduces it. Derek's 6.4 run on the real code is still the one that counts: it reports which tests turn red under each mutation.
- **Fakes.** Tests drive the real parser, binder and renderer. Only the host's theme is faked, with `fakeTheme()` (`tests/fake-theme.ts:5`), and readings come from the `seed` the tests already use.
- **Configuration.** Every test that needs a document goes through `readDocument` (`tests/configuration.test.ts:33-44`: a `mkdtemp` directory, `readConfiguration({ agentPath, … })`) or `useTempAgentDir` (`tests/jefferson.test.ts:171-180`). No task reads or writes `~/.pi/agent/pi-jefferson.json` (`owner-rulings.md`, 2026-11-06).
- **Logging and errors.** The change adds no use case, adapter or entry point, so no task adds a log line, a flag or an error path (design D8). The rejection of a non-string label is untouched and stays covered by `tests/configuration.test.ts:710-715`.
- **Not tasks.** Markdown documentation (README, ARCHITECTURE, ADRs) is the docs pass. The living spec is brought in line by sync at archive. No task merges, pushes or fast-forwards.
