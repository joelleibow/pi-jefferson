Tasks are Derek's unless marked Joel's. Sources: `design.md` (D1 to D12, cited as D#), `specs/extension-source-layout/spec.md` (cited by requirement name), `research-eleanor.md` (cited by section; "Add. 2" is Addendum 2, the mutation runs).

**How the groups work.**

- This is a behavior-preserving refactor, so there is no new behavioral test to write. A task "starts red" in one of two ways (D10.1): its pin line or test specifier names a file that does not exist yet, so the suite fails to load; or a named mutation turns an existing entry-driven test red. Each extraction task names its mutations from Add. 2, with the tests that go red. Derek applies the mutation to the new file, shows the named tests red, reverts it, and shows the suite green.
- Where Add. 2 measured a mutation green, the task says so and claims nothing for it. A mutation Eleanor did not measure is marked **unmeasured**; Derek reports what turns red, and a mutation that turns nothing red is a gap he reports (D "Risks / Trade-offs"), not one he ignores.
- Each group is one commit on the branch. `pnpm typecheck` and `pnpm test` pass at each (D "Migration Plan"). Any group reverts alone. No task merges or pushes.
- `/tmp/import-graph.cjs` (task 1.2) runs from the repository root as `node /tmp/import-graph.cjs`. Every "graph check" below means that run. It is not committed.
- No task edits `~/.pi/agent/pi-jefferson.json` (Joel's file). A check that needs a configuration uses a scratch agent directory through `PI_CODING_AGENT_DIR`, as the existing tests do (Eleanor §4, `useTempAgentDir`). Task 1.1 and task 11.8 show that the file is untouched.
- **Logging and error handling.** The change adds no use case, adapter behavior or entry point. `feedSessionData`, `installFooter` and `startUp` are existing code moved out of the entry; the code logs nothing today and the design adds nothing (D "Migration Plan": the evidence shows no logging to add or keep). `readConfiguration` still returns its warning and the install still calls `ctx.ui.notify(warning, "warning")`; tasks 4.1 and 8.1 keep that and the existing tests at `tests/jefferson.test.ts:264-279` and `:533-541` prove it. No task adds a try/catch or a log line.
- **Outside this list.** The GitHub description (`gh repo edit --description`) is the conductor's, after the code pull request merges (D12.1). Markdown documentation is the docs pass's.
